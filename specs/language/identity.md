# Stable identity rules

Every declaration has a **stable identity** `package/module/symbol` that is
independent of the file it lives in. Moving `orders/order.forge` to
`sales/order.forge` changes nothing wire-visible.

| identity | form | derived from |
| --- | --- | --- |
| package | `@acme/commerce` | `forge.toml [package].name` |
| module | dotted path or `_` for the default module | `module` declaration, else default |
| symbol | declared name | the declaration |
| stable id | `@acme/commerce/_/Customer` | package + module + symbol |
| operation id | `<stable id>.<operation>` e.g. `@acme/commerce/_/Customer.create`, `.../Order.status.submit` | derived |
| wire name | `customer`, `order_events` | symbol in the target case; overridable **only** through a reviewed rename |
| physical name | `customer` (D1 table), access-partition prefix (Dynamo) | wire name + physical naming version; stored in the migration ledger |

- A **rename** is a compatibility operation: `forge migrate rename Customer Client`
  records `Customer → Client` so the physical name and outstanding cursors
  survive. Editing the symbol without a recorded rename is a compile error
  against the previous baseline (E-ID-001), not a silent new resource.
- Display labels (`@label("Client")`) never affect identities.
- Enum members: identity = enum stable id + member name; wire value defaults
  to the member name. Changing a wire value is a rename.
- Lifecycle actions: `<resource>.status.<action>`.
- Messages: `<channel stable id>.<message>`; an imported channel keeps the
  **upstream** stable id as its contract identity and gets a local binding id.

## Deterministic infrastructure identities

Infrastructure names are derived from stable ids plus the deployment's
`stage` and a physical naming version, never from source order or file paths:
`forge-<stagehash>-<wire name>`. They are recorded in the build plan and are
the key of the migration ledger. Runtime record IDs are generated by the
injected `IdService` and are unrelated.

## Build identity

`build_id = hash(sources, dependency content hashes, compiler version, stdlib
version, target capability-manifest versions, build options, previous schema
baseline)`. Two builds with the same inputs produce byte-identical artifacts
(M1 gate).
