# Canonical wire format (portable-v1)

All public APIs speak strict canonical JSON, `application/json; charset=utf-8`.
Import profiles (CSV/XLSX) have their own permissive decoders; they never
change API behaviour.

## Values

| Forge type | JSON | canonical form | rejects |
| --- | --- | --- | --- |
| `id` | string | generated by `IdService`; opaque; ≤ 64 chars `[A-Za-z0-9_-]` | anything else |
| reference (`Customer`) | string | the referenced `id` | objects |
| `text` | string | after declared normalizers; NFC; no lone surrogates | control chars other than `\t\n\r` |
| `integer` | number | exact integer in `[-(2^53-1), 2^53-1]` | fractions, exponent notation producing non-integers, out of range |
| `decimal<s>`, `money<CUR>` | **string** | `-?[0-9]+(\.[0-9]{1,s})?`, no exponent, no leading `+`, scale ≤ declared | numbers (E-WIRE-003: precision loss) |
| `boolean` | boolean | | strings `"true"` |
| `date` | string | `YYYY-MM-DD` proleptic Gregorian | times |
| `datetime` | string | RFC 3339 UTC at declared precision, `Z` suffix, e.g. `2026-09-20T14:03:00.000Z` | offsets other than `Z` (they are accepted on **input** and normalized to UTC) |
| `localTime` | string | `HH:MM[:SS]` | offsets |
| `duration` | string | ISO 8601 fixed-unit subset `PT..` (`PT90S`), or integer ms? — **decided: string ISO 8601, seconds/minutes/hours/days only** | `P1M` (calendar months) |
| enum | string | the member's wire value | case variants |
| shape | object | fields in declaration order on output; any order on input | unknown fields (E-WIRE-010) |
| `T?` | value or `null` | see absence rules | |
| list | array | bounded by declared max | |

## Absence versus null

- **Create**: an optional field may be absent or `null`; both store "unset".
  Defaults apply only when the field is **absent**; an explicit `null` on a
  defaulted optional field stores null (does not reapply the default).
- **Read**: every declared field is present; unset optionals are `null`.
- **PATCH**: absent means unchanged; `null` clears an optional; `null` on a
  required field is E-WIRE-011.
- Server-owned fields (`id`, `version`, `createdAt`, `updatedAt`, `deletedAt`,
  lifecycle status, derived `:=` fields) are rejected on any write with
  E-WIRE-012 (no silent mass assignment).

## Records

```json
{
  "id": "cus_01J...",
  "version": 3,
  "createdAt": "2026-09-20T14:03:00.000Z",
  "updatedAt": "2026-09-20T14:05:10.000Z",
  "deletedAt": null,
  "code": "ACME",
  "name": "Acme",
  "email": null,
  "tier": "gold"
}
```

`version` is a positive integer, incremented by every committed mutation.
Reads set `ETag: "<version>"` (strong). Mutations over HTTP require
`If-Match: "<version>"` (else 428); direct SDK commands carry `expectedVersion`.

## Pages

```json
{ "items": [ ... ], "next": "<opaque cursor>" | null, "limit": 50 }
```

Cursor = base64url( HMAC-protected { q: operation id, v: contract version,
t: tenant fingerprint, k: last sort key(s), id: tie-breaker, c: consistency } ).
Default `limit` 50, max 100. No snapshot guarantee across pages.

## Problem details

Errors are RFC 9457 `application/problem+json`:

```json
{
  "type": "https://forge.dev/errors/version-conflict",
  "title": "Version conflict",
  "status": 412,
  "code": "VersionConflict",
  "detail": "expected version 3, current is 4",
  "requestId": "req_...",
  "retryable": false,
  "fields": [ { "path": "email", "code": "InvalidEmail", "message": "..." } ],
  "constraint": "@acme/commerce/_/Site.unique.code_within_customer"
}
```

`code`, `retryable`, `fields[].path`, `fields[].code`, and `constraint` are the
stable Forge extensions; `detail` is human text and not a contract.
