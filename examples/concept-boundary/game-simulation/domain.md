# Authoritative multiplayer simulation

A session owns one authoritative WorldState. Clients submit sequenced commands for target ticks; SealInputs selects and seals the admitted ordered batch. AdvanceWorld alone transitions WorldState and emits TickCommitted. ProjectClients sends derived snapshots; client-side prediction has no authority over durable world state. VerifyReplay records whether a pinned checkpoint, accepted input log and rules build reproduce the expected digests.

A concrete tick admits commands before a cutoff, rejects duplicates and invalid actions, orders accepted commands by a specified stable key, samples the declared random stream, computes collision effects, and commits the next tick only against the preceding digest. Lost tick requests are retried with tick identity; two replicas cannot both become semantic owners. Admission, compare-and-swap, randomness and physics determinism are obligations of the implementation, not executed by the JSON corpus.

Late input is rejected or deferred according to the session rules; this example does not retroactively rewrite committed ticks. Prediction rollback occurs in the client realization and may use the server snapshot, but cannot change the authoritative batch. Replay failure records the first divergent tick and retains both digests. A patched ruleset requires an explicit new session/replay boundary; it is not silently considered the same experiment.

Stress cases include a reconnecting client replaying sequence numbers, server restart after batch sealing, duplicate tick delivery, a missing checkpoint, mismatched physics build, wall-clock access during simulation, and platform-dependent floating-point results. This fixture does not implement a game engine, network stack or deterministic physics solver.

Request/admit protocol: AdvanceWorld's physics input is optional. InputBatch activation exports PhysicsRequest with sessionId, tick, prior state digest and inputBatchDigest; it emits neither WorldState nor TickCommitted until CollisionReady provides a matching result. The L1 adapter retains pending batch correlation and deduplicates replies. Initialization uses the pinned session checkpoint. VerifyReplay similarly exports ReplayRequest first and emits ReplayChecked only after VerdictReady whose embedded request matches the original request. A request activation binds its payload to the request input; the adapter retains it across the asynchronous reply. InputBatch and TickCommitted explicitly preserve sessionId. These branch/admission rules are obligations, not implemented behavior or an implied atomic external transaction.
