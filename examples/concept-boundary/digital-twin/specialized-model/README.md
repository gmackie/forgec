# Modelica / SSP interface handoff, not an executed simulation

`ThermalPlant.mo` is a representative equation-based lumped thermal model using SI units. `SystemStructure.ssd` is an SSP 2.0 XML interface sketch exposing heatFlow (W), ambientTemperature (K) and temperature (K). Its component references `resources/ThermalPlant.fmu`, intentionally absent. This directory is neither an FMU nor a complete SSP archive. SSP 2.0 retains SSP1 namespace URIs; the version attribute selects 2.0.

Python ElementTree parsed the XML and checked system/component names and input/output directions against the Modelica declarations, units and exact connection endpoints. Run `python3 check_interface.py` from this directory to repeat those checks. Exact input hashes and tool limitations are in verification.json. No OpenModelica executable was available (`command -v omc` found none). No Modelica compilation, SSP XSD validation, FMU export, FMI compliance check, numerical integration or physical validation was performed.

RunPlantSimulation `#input:request` / `#output:request` carries SimulationRequest to SimulationMaster. RecordSimulation `#input:report` admits SimulationReport to `#output:record` and `#output:recorded`. Model/assembly/calibration/scenario digests and numerical settings identify the requested run. A future worker must produce trajectory and diagnostic digests and echo the canonical request digest. The static interface receipt is not a successful SimulationReport and cannot stand in for one.

To make this executable, validate physical parameters, compile/export the FMU with a named tool and FMI mode, verify its modelDescription interface, package it into SSP, supply scenario inputs/parameters, and record solver/tolerance/platform settings. These are missing artifacts and verification steps, not claims about shipped functionality. The equation and XML are intentionally readable review artifacts while the content-addressed handoff can carry full binaries later.
