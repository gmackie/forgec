# Quota and allowance

Foundation system for #106. Allowance binds an exact policy specification, Entitlement and scope, Usage dimension/unit, limit, warning threshold, measure and enforcement metadata. Renewals preserve the predecessor and the source grant lineage; elapsed periods never mutate into a new entitlement. Source revocation or expiry makes a projection inactive. Quota does not grant authorization.

Windows are explicit: Fixed uses the allowance validity interval; Rolling uses the preceding windowSeconds; Tumbling resets at intervals anchored to validFrom; CalendarDay/Month/Year reset at UTC boundaries. Calendar periods are clipped to allowance validity. UTC is the supported calendar profile; other timezones fail validation rather than silently applying a wrong DST boundary. All consumption intervals are half-open and stop at the decision instant. Events exactly at that instant contribute to a later projection. Usage intervals crossing a boundary require explicit domain allocation, not implicit proration.

Usage remains authoritative for consumption and corrections. Occupancy counts current committed Allocation reservations and allocations at the requested slot. UsageAndReservations adds only outstanding reserved claims to usage: applications must record actual consumption when committing allocations. Allocation owns claim expiry/release. Its projection uses the current journal, not reconstructed historical state. Returned usage event IDs, reservation IDs and allocation journal head explain the projection; current corrections can change a later projection of the same window.

Quotas.inspect returns exact six-decimal usage, reservations, remaining capacity, requested quantity and projected total. Remaining may be negative. Exceeding a Hard limit returns Prohibit; Soft returns Warn. Warning thresholds do not themselves prohibit, and a request exactly equal to the limit does not exceed it. These are read-only policy decisions, not admission tokens: simultaneous callers can observe the same remaining amount. L1 execution must atomically couple a fresh limit guard with consumption/reservation writes. Gatekeeper separately decides authorization.

QuotaCounter optionally binds a Ledger account with the same unit and an exact source policy. It is realization metadata, not another authoritative usage meter. The fixture mirrors the same consumption with a ledger counter and verifies equality without changing semantic quota identity; window partitioning, correction/reconciliation and atomic enforcement belong to that realization. The default projection uses Usage and Allocation directly.

Typed fixtures cover API/token budgets, licensed seats, benefit holds and machine capacity. Tests exercise memory, SQLite and PostgreSQL, reset boundaries, renewal, revocation, corrections, counter parity and hidden history. No hosted provider enforcement certification is implied.
