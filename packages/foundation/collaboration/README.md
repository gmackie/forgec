# Collaboration

Typed Discussable sidecars compose Participation and immutable Artifact revisions. Entries, corrections, reactions, mentions and attachments are immutable candidates. Only events in the serialized ThreadEvent journal are authoritative activity; use Collaborations.activity() to rebuild and authorize the complete projection. Closed threads reject new activity until an explicit Reopen event. One unique thread/sequence guard resolves concurrent publication and close races. Identical reactions share entry/author/code uniqueness. Publication retries use the same idempotency key and expected predecessor.

Journals are bounded to 128 events; exceeding the bound fails explicitly. Staged candidates can survive an interrupted or rejected publication and are not activity. Kernel policies must limit raw journal writes to trusted publishers; generated candidate writes check reference existence, while publication and projection explicitly authorize referenced identities. Backdated ParticipationEnd facts can make historical activity fail validation; governance must control retroactive membership changes. Caller capability checks remain separate from membership. Redaction/deletion is not offered by this append-only package.

Synthetic KanBangerIssue, ForgeGraphDeployment and LevelForgeCandidate consumers exercise the exported facet; they are contract probes, not inspected application integrations. Local generated memory, SQLite and PostgreSQL tests cover retained corrections, attachment pins, race conflicts, lifecycle, idempotency, hidden references and tenant boundaries. Hosted D1/DynamoDB certification remains pending.
