Overview

A Cloudflare Kumo + React management console and Effect backend for independently operated Forge registries. Package contracts remain separate from app registrations and environment configuration. The existing Registry and Catalog enforce signed artifact integrity. A standards-based OCI adapter stores manifests, blobs, signatures and published metadata in an operator-selected OCI Distribution registry. The catalog is derived from verified OCI artifacts.

Architecture

Kumo / React → same-origin authenticated API → Effect service → OCI Distribution registry for artifacts and published metadata; D1 (Workers) or SQLite (Docker) for mutable app configuration.

One administrator credential per instance, supplied by its operator. Browser credentials remain in memory. Each instance has its own authority and signing key. No analytics, remote fonts, automatic federation, central login, or phone-home traffic. Endpoints registered for apps are metadata, not automatically contacted.

Goals & Non-goals

First build

  • Create, edit and archive app registrations.
  • Add and edit environment endpoints, targets, plain configuration and secret references.
  • Publish immutable signed compiled bundles; browse exports, actions, fields, dependencies and digests; download verified bundles.
  • Inspect instance settings and recent administrative activity.
  • Run the same flows on Workers and persistent Docker.

Separate follow-up capabilities

  • Compiler execution, infrastructure deployment and live health probes.
  • Team RBAC/OIDC, remote registry federation and grant approval workflows.
  • Secret-value storage; configuration stores provider secret references only.

Risks & Mitigations

  • The existing library uses Node builtins: use Workers nodejs_compat and verify the actual Worker locally.
  • Concurrent administrators: require revision preconditions and atomic storage compare-and-swap; conflicts never overwrite silently.
  • Publication is not deployment: mark registrations as unverified and never invent health, usage or deployment evidence.
  • OCI is the registry source of truth, not a database copy. App configuration uses bounded atomic documents separately. OCI credentials and signing keys are server-only. Tags are discovery pointers; pinned pulls use manifest digests.
  • Secret references and signing credentials: private signing keys stay server-side; uploaded bundles must exclude environment secrets and implementation code.
