Forge: what exists and what blocks public beta

Review date: 2026-10-15 · baseline d2720736e302 · FORG-20 / FORG-6

Forge already has a broad domain language, multi-host runtime and a large business-domain library. The next beta milestone is a reproducible, authenticated application installed from published artifacts. Current source capability substantially exceeds what users receive from the public 0.4.0 packages.

Recommendation: finish package identity and Forgejo release verification, then certify and install a single advertised Cloudflare release path. Continue transactions and typed queries without broadening the beta claims ahead of evidence.

Language and compiler

Implemented in source

Rust lexer/parser and formatter, package/dependency resolution, typed references, enums/shapes/refinements, resource CRUD and lifecycle/rule contracts, views/projections/caches, workflows, schedules, and edition-2027 structural facets. The compiler emits DomainIR, physical data plans, migration artifacts, typed clients, OpenAPI/Smithy and contract IR.

Limits and remaining work

It is a domain language plus handwritten Effect behavior. Host extension routes, Cloudflare tunnels and authentication composition are APIs/configuration; they are not all new .forge grammar. Filtered query expressiveness remains FORG-16.

Source and evidence

docs/language.md · crates/forgegraph-cli/src/main.rs · crates/forgegraph-semantic/tests

CLI, editor and onboarding

Implemented in source

forgec init/check/fmt/build/lock/inspect/compat/migrate/import-openapi/import-contract/contract-diff/explain, concept contract tools and the LSP. PR59 adds a dependency-free starter; editor navigation/completion and compiler diagnostics are exercised by CLI tests.

Limits and remaining work

Current public 0.4.0 does not contain recent source changes. Init compiles a package; it does not install a runtime, start a host or deploy. All 42 CLI/unit/composition tests passed again in this review; this is not a full Rust workspace certification.

Core data, validation and transactions

Implemented; bounded experimental transactions

Memory, SQL/D1, PostgreSQL/libSQL and DynamoDB adapters; optimistic versions, unique claims, guarded references, soft deletion, audit/outbox, mutation receipts and changesets. Sequential transaction bodies see staged records and complete bounded snapshots with resource revision checks. Compatible DynamoDB entity/counter writes compose atomically.

Limits and remaining work

32 mutations/32 resources; 4096 rows/64 pages per resource snapshot. Repeated temporal/hierarchy mutations and incompatible physical actions fail closed. Every writer must upgrade or be fenced. FORG-15 stays open. Fifteen provider traces establish their named scope only.

Source and evidence

docs/transactions.md · packages/runtime/src/transaction.ts · conformance/transactions/evidence/2026-10-15.json

Authentication, authorization and ingress

Implemented adapters; application policy required

Fail-closed AuthHost, JWT and workspace session/API token adapters, purpose/gatekeeper checks, tenant scopes, signed raw-body HMAC webhooks, bounded binary endpoints and SSE/response streams. Workspace selection is deployment-owned; memberships and token authority remain application-owned.

Limits and remaining work

This is not a login product or credential issuer. Node/Workers stream responses; the Lambda/API Gateway path buffers and rejects declared streaming. Cross-process isolated-callable assurance remains withheld.

Source and evidence

docs/application-auth.md · docs/signed-webhooks.md · docs/streaming-http.md

Queues, workflows and schedules

Implemented in source

Atomic messages/outbox, subscription progress and deduplication, poison/redrive paths, portable workflow executor with durable host drivers, correlation/wait/sleep/error branches and occurrence-based schedules. Global/idle-tenant schedule fixes are tracked as delivered.

Limits and remaining work

At-least-once delivery requires idempotent consumers. Workflow history is not portable across native drivers; deployment, cancellation and replay guarantees must be stated per profile. Native external effects do not roll back with storage.

Source and evidence

docs/subscription-delivery.md · packages/runtime/src/workflows.ts · packages/runtime/src/schedules.ts

WebSockets and MQTT

Implemented typed bindings and transports

WebSocket stream sequencing/replay and explicit gaps; MQTT broker adapter, typed channel bindings and authenticated inbound command consumption; optional Mosquitto broker deployment projection. The runtime can connect an existing broker and project a self-hosted broker.

Limits and remaining work

No managed Cloudflare MQTT broker is provisioned by the language annotation. Authentication/topic tenancy, broker lifecycle and limits remain deployment responsibilities. Realtime guarantees are bounded and at least once.

Source and evidence

docs/realtime-transports.md · packages/runtime/src/mqtt-consumer.ts · packages/adapters/src/mqtt-broker.ts

Artifacts, journals and vault integration

Implemented; write paths differ by host

Pinned trees/blobs, expected-ref publication guards, idempotent outcome journals, uncertain-result recovery, materialization and history/rollback tooling. Bob opt-in adapters and actual application-seam evidence exist. External drafts were imported in the earlier vault migration work.

Limits and remaining work

The Git preparation/publication adapter requires Node/Git. Workers-native artifact writes remain FORG-19. Isolated harness and source linkage do not establish current production adoption or a generic atomic transaction across Git and metadata.

Console, generated UI, registry and governance

Implemented; stability varies

Console for model editing/build/package workflows and OCI publication; descriptor-driven React forms/workspaces; interface/MCP/RPC/GraphQL tooling. Registry SDK covers signed artifacts/catalog/grants/snapshots/evidence. Governance models rights/disposition/lineage/suppression; release-gates consumes compatibility/evidence.

Limits and remaining work

Console is a private app, SDK registry is public, private npm registry service belongs to ForgeGraph. Experimental SDKs require exact pins. Security docs explicitly withhold unproven isolation; governance mappings are not compliance certification.

Source and evidence

Verification and operational evidence

Strong retained tests; freshness is a release gate

15 portable conformance scenarios; differential comparisons; Foundation contracts and generated consumers; installed-tarball checks; named real provider suites; migration/export/fence protocols; security and compatibility regressions. PR58/59 exact-head Forgejo checks passed before merge.

Limits and remaining work

Public distribution and release operations

Release blocking gaps confirmed

All nine public npm identities and all five publishable compiler crates were observed at 0.4.0. Source manifests are 0.5.0. Public SDK names are preserved; canonical metadata is corrected to Forgejo. New ownership checks and a Forgejo release rehearsal are being prepared.

Limits and remaining work

GitHub CI/release/mirroring workflows were still present at baseline and are removed in this change. Rehearsal never publishes. Authenticated npm permission, current certification, publication/asset delivery and actual install rehearsal remain FORG-6. Private service naming remains FORGE-117.
