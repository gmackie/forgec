2026-10-15 · gmackie/forge · FORG-21-beta-onboarding

Overview

Ship an installable compiler and matching runtime with a documented path from a small language package to an authenticated Cloudflare application. Recommend Cloudflare as the initial launch path. Describe AWS and Node support by verified profile; current source features alone do not establish certification or release availability.

Goals & non-goals

The beta must make its supported language, provider limits and upgrade rules explicit. Keep building the language against concrete application needs. No production cutover, fleet maintenance or new tunnel/DNS changes are part of this release-preparation slice.

Risks & mitigations

Transaction resource revisions require all writers to upgrade or be fenced before activation. The current transaction contract remains experimental and bounded. Pin exact experimental package versions. Do not transfer old provider receipts onto changed source or treat narrow transaction traces as full application certification.

Verification and release decision

Use Forgejo CI only. Every PR must pass checks for its exact head before automatic approval/merge. Beta announcement requires actual published artifacts, a clean install rehearsal, current source-bound certification for the advertised profile, documented auth/migration/rollback behavior, and a signed manifest that lists uncertified profiles honestly.

Open questions

Final beta version and package ownership await the FORG-20 inventory. Cloudflare-first is the recommended launch scope, not a claim that AWS/Node have been removed or certified. Broader deployment changes require their own tracked delivery evidence.
