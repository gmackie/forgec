Overview

Browse resources, functions, sources, shapes, purposes, capabilities and other declarations across the application. Choose an item to read its fields, constraints and behavior. Enable editing explicitly, then review the source changes before creating a Git commit.

Goals & Non-goals

Use native Forge syntax trees and taxonomy. Preserve lossless edits and browser-local drafts. Support real GitHub commits on Docker and Workers without a central Forge service. Automatic merges, pull request creation, other Git providers, app deployment and OCI publication are outside this pass.

Risks & Mitigations

GitHub expectedHeadOid atomically rejects stale commits. Source paths stay inside an operator-configured root and only regular Forge files are editable. Tokens remain server-side. Full repository trees must be complete before computing deletions. Replacement dialogs explain draft and undo-history loss. Source editing commits a local text draft on blur so compiler refresh does not interrupt typing.

Verification

Test read/edit boundaries, shared-purpose editing, source preservation and uninterrupted typing, defaults and undo, browser persistence, commit review, conflict preservation, invalid API input, path traversal, symlinks and provider errors. Verify real commits on a temporary branch and remove that test branch afterward.

Open Questions

Which repository, branch and source root should the production application connect to? Integration is implemented; configuration waits for the user's answer.
