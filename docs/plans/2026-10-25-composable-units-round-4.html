Where the manifest pointer lives (FORG-47)

Durable Object Recommended

  • Strongly consistent: one object holds the current closureHash per entry point, versioned with a compare-and-swap.
  • Isolates cache it briefly and revalidate. A swap is visible within a known bound.
  • The same object can own the tier stats, fixing the per-isolate counts.
  • Cost: one DO read on a cache miss.

Workers KV

  • Cheap reads at the edge.
  • Eventually consistent, up to about 60 s, so a swap can still serve a mix of old and new for a minute.
  • Doesn't fit "fall back, never hide"; the stats problem stays.

Redeploy the host

  • Bake the manifest into the host script.
  • Every swap becomes a deploy, which defeats linker B's point.

Tracks

  1. FORG-47: shared manifest pointer and stats for linkers B and C

    Parallel

    A Durable Object holds the current manifest and closure hashes, with a versioned CAS on swap and a bounded revalidation window in each isolate. Tier stats move into the object. Tests show a swap reaching every isolate; local workerd runs several isolates. A deployed re-check reuses r4-deployed through a temporary stage.

  2. FORG-48: faster loader misses

    Parallel

    Content-addressed caching of unit code by unitHash: the Cache API, or a small per-closure bundle in the pointer object. Measure placement (Smart Placement or a co-located D1) for the 15 ms D1 round trips. Target: a warm-host miss under 100 ms deployed, or explain why that isn't reachable.

  3. FORG-49: replace the call counter with a depth guard

    Parallel

    Guard on nesting depth (limit 32; refuse at 30 hops) instead of total calls. Move queue, cron and workflow start/signal back to the shared runtime, and re-measure deploy bytes and the linker-A differential at 15/15.

  4. FORG-50: build service — forgec in a Worker emits units

    Parallel

    Extend crates/forgegraph-wasm (T1) from check/build to units/plan.json, the Closure Manifest and per-closure bundles, read from a SourceTree over Artifacts or Loom. It must be byte-identical to native forgec on acme, and it reports CPU and wall time per build in a Worker.

  5. LOOM-19: Session previews on isolates

    After FORG-47 and FORG-50

    A Session write triggers the build service, then PlanSessionRebuild, then only the changed closures are pushed to the dynamic tier under a session-scoped pointer. A preview URL serves the Session's code, and packed scripts are never re-uploaded. Staging and production smokes cover it.

Scope

Goals

  • Swaps that are correct across isolates
  • Loader misses priced and reduced, measured deployed
  • One Session edit → isolate preview, end to end
  • Compiling on Workers, not only checking

Not in this round

  • The Forge-native behaviour language
  • Compiling TS to WASM
  • Changing Loom's byte-canonical storage (ADR 0093)
  • Serving customer traffic through linkers B or C

Risks

Medium forgec in WASM may exceed Worker CPU or memory for a full unit build. FORG-50 measures it first. The fallback is the same pipeline in a Container or on hetzner-build, keeping the API.

Medium FORG-47 and FORG-48 both touch the linker-dynamic host. Ownership is split: FORG-47 owns manifest resolution, FORG-48 owns unit fetching. Rebase order follows merge order.

Low Deployed re-checks need temporary stages, and ForgeGraph can't remove a stage yet (FORGE-219). Reuse forge-console's retired staging stage and its targets rather than creating more.

Verification

Every track keeps the linker differential at 15/15 (whole-app, A, B, C), reproducible bytes, and green Forgejo CI at the exact head. Deployed numbers are labelled measured-deployed, and anything not deployed is labelled local. LOOM-19 is closed by production smoke evidence. Its production.healthy receipt depends on FORGE-217.

Outside this round: ForgeGraph gaps found

FORGE-217: no health receipts for apps with both staging and production; deploy promote is a no-op; PRs contained in a deployed commit are never receipted. It blocks closing LOOM-13, 15, 16, 17 and 18.

FORGE-219: stages can't be torn down; FG_COMMIT_HASH misses generated configs; branch deploys need break-glass.
