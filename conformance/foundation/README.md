# Foundation verification

This directory separates package contract validation from executable semantics.

```sh
pnpm foundation:contracts
pnpm foundation:composition
```

The first command validates all 41 package contracts, catalogs, issue coverage and dependency direction. It does not mark their acceptance cases passing. The second compiles an explicit package deployment twice into private temporary directories, compares artifacts and runs generated-bundle runtime tests. It verifies a minimal application sidecar, dependency function registration, tenant/reference integrity and explicit remote bindings. It is not the complete G1 gate: facets, patterns, source provenance, local nested callable transactions and provider certification remain separate.

`fixtures/composition/` contains synthetic compiler/runtime probes, not the Foundation Evidence implementation. `composition.app.json` is generated by `scripts/refresh-fixtures.sh`; ordinary runtime tests consume that checked-in bundle and CI checks for drift. The dedicated runner consumes a fresh build instead.

Provider mode deliberately exits nonzero until real required-provider verification exists. Package-local implementation verification also fails explicitly for planned packages. A missing verifier is not a successful or skipped acceptance case.

The memory atomicity regressions and known required-but-failing probes are documented in `docs/foundation/kernel-gaps.md`. The published execution plan is https://syhczsdoad8z.postplan.dev.

`pnpm foundation:local` verifies every package in dependency order, failing before execution if any verifier is missing. Set `FORGE_FOUNDATION_PG_URL` to include isolated PostgreSQL schemas; otherwise the local suites run memory and SQLite only. Local receipts never certify hosted D1 or DynamoDB.
